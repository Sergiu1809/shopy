# Tests — GH-13

> Written by the test author before any code. Every new test failed first, for the right reason.

## Summary
- Added: 111 test functions (168 cases with parametrization) · 36 unit (56 cases), 75 integration (112 cases). Files: `backend/tests/test_chunking.py`, `test_embeddings.py`, `test_usage_ledger.py`, `test_indexing_schema.py`, `test_outbox_hooks.py`, `test_worker.py`, `test_reindex_all.py`, plus 3 new tests at the end of `test_seed_load.py`. Support: `backend/tests/stubs.py` (`StubEmbeddingProvider`, `stub_vector`), `backend/tests/indexing_data.py` (row helpers for committed databases), `backend/tests/conftest.py` (N12 guard, `indexing_template` / `indexing_db` / `indexing_sessionmaker`).
- Approach:
  - Pure rules (chunk text, hash, cap/price parsing, cost math, provider request shape) are unit tests with golden strings; chunk functions get transient ORM objects.
  - Admin hooks: HTTP tests with PATTERN-015 (rolled-back `session`); only outbox rows newer than the test's starting `max(id)` are compared.
  - Worker: `indexing_db` is a per-test database cloned (`CREATE DATABASE … TEMPLATE`) from a template migrated once through Alembic, so `process_next` can open and commit its own transactions. The provider is always the injected stub; it records every call and can fail, hold the call open (`gate`) or return wrong-size vectors.
  - Embeddings, chunks and the ledger are read back with plain SQL (`embedding::text`, `vector_dims`), never through the pgvector codec.
  - N12: `OPENAI_API_KEY` is popped at conftest import; an autouse fixture replaces `app.indexing.embeddings.AsyncOpenAI` and `openai.AsyncOpenAI` with a function that calls `pytest.fail("real OpenAI client constructed in a test")`. Until `app.indexing` exists the fixture is a no-op (same pattern as `_reset_rate_limits`), so the earlier suite keeps running.
- Red state (2026-11-26, before any product code): `pytest --continue-on-collection-errors` → **69 failed, 5 collection errors, 533 passed**.
  - 5 files fail at import, every test in them (102 cases): `test_chunking.py` (20), `test_usage_ledger.py` (23), `test_worker.py` (48), `test_reindex_all.py` (8): `ModuleNotFoundError: app.indexing` / `app.usage`; `test_embeddings.py` (14): `ModuleNotFoundError: openai` (dependency not added yet; `app.indexing` missing too).
  - 55 new DB cases fail on `UndefinedTableError: relation "reindex_outbox" / "kb_chunks" / "usage_ledger" does not exist`: `test_indexing_schema.py` (28), `test_outbox_hooks.py` (24), the 3 new `test_seed_load.py` tests.
  - 14 cases of the A11-extended expectations fail on the set/column comparison (tables, columns, nullable set, FK rules, `store_id` tables, head `"0001"` ≠ `"0002"`; the 3 new `columns_match_brief` cases and the 3 new `ids_are_bigint_identity_always` cases fail with `KeyError: 'id'` / missing columns).
  - Every other existing test passes (533).
- Checked against a throwaway reference (scratchpad only, never in the repo) so the tests are not wrong themselves:
  - With a scratch `0002` DDL copied in temporarily: all schema tests pass. The positive hook tests fail on behaviour (`[] == [("product", id, "update")]`), the seed enqueue tests fail on behaviour, and `test_models_match_migration` fails because there are no models yet.
  - With a scratch implementation of chunking, ledger, provider, outbox and worker: all 141 cases of the unit, worker, reindex and schema files pass, twice in a row.
  - That run found one test bug, fixed before the commit: `test_only_new_chunks_are_embedded` shortened a review so much that it packed back into one chunk.
- Existing tests changed: 2 files, additions only (A11, approved at gate B): `test_migrations.py` (`TABLES` += 3; head `"0001"` → `"0002"`), `test_schema.py` (`TABLES` += 3; `EXPECTED` += 3 tables; `NULLABLE` += 6; `SET_NULL = "n"` added to the rule constants; `FK_DELETE_RULES` += 2; `store_id` set += `kb_chunks`). `test_seed_load.py`: 3 tests and one helper appended, nothing existing touched. Removed: 0.

### Interfaces the tests settle (the plan names these, but not every argument)
| What | Settled as | Why |
|---|---|---|
| `product_text` | `product_text(product, category_name, variants) -> str`, ORM objects; it orders variants by `id` itself | the worker has these objects; the order rule is the function's |
| `review_chunks` | `review_chunks(reviews) -> list[str]`, ORM `Review`s in any order; it sorts `(created_at, id)` | same |
| `policy_chunks` | `policy_chunks(title, body) -> list[str]` | A4 text is `title\n\nbody` |
| Policy split | units are `title` and each `\n\n` paragraph, packed greedily with `\n\n`; `"\n\n".join(chunks)` equals the full text | "split at blank lines" (B2) |
| `IndexingConfig` | tests only call `IndexingConfig.from_env(<dict>)`; it must **not** raise on bad values (they block the row inside `process_next`) | fields stay the builder's choice |
| Empty values | `EMBEDDING_MODEL=""` and `OPENAI_API_KEY=""` count as not set, like the price and cap | Compose passes empty variables as `""` |
| `NaN` | `DAILY_COST_CAP_EUR=NaN` and a `NaN` price are invalid | A7 "not a number" |
| Blocked messages | exact: `EMBEDDING_MODEL is not set`, `OPENAI_API_KEY is not set`, `<PRICE> is not set` / `is invalid`, `DAILY_COST_CAP_EUR is invalid`, `daily cost cap reached` | plan § Cost gate |
| Error text | provider: `openai <Class> (<status>)` exactly; other: `<Class>: <message>`, cut to exactly 500 characters | A8 |
| The loop | `worker.__main__.run(sessionmaker, provider, stop: asyncio.Event)`; reads `os.environ` per row; returns once `stop` is set, without waiting out the idle 2 s | the plan gives `asyncio.run(run(...))` only |
| Loop log | a missing table logs a line containing `reindex_outbox missing; waiting for migrations` (any level ≥ INFO, logger `worker` or `worker.*`) | plan § loop |
| `reindex_all` | `worker.reindex_all.main()` (sync; reads `DATABASE_URL`) prints `Reindex: enqueued N sources.` | plan § Full reindex |
| `Outcome` | an enum with exactly `IDLE`, `DONE`, `BLOCKED`, `FAILED` | plan § Worker |
| Unique key name | asserted by prefix `uq_kb_chunks_` and by its columns; the naming convention gives `uq_kb_chunks_source_type_source_id_chunk_index`, not the plan's `uq_kb_chunks_source_type` | the convention decides the name |
